# 飞鸽外呼平台（上游）可行性侦察报告

> 阶段：Step 1 — 上游可行性侦察
> 日期：2026-11-13
> 方式：真实浏览器登录（Playwright 驱动 Chrome 152，headful）+ 纯 HTTP/WS 探针验证
> 测试账号：156****0075（某网络科技有限公司（脱敏），tenantCode=24421，坐席：宋××）
> 结论：**可行**。上游具备完整的「列表 / 详情 / 录音 / 转写 / 呼出 / 实时通道」接口，且除登录滑块外全部可用纯 HTTP 调用，本地平台无需长期驻留浏览器。
> 注：转写接口实测可用但**v1 不使用**（全部转写自建，见 §5 顶部决策说明）。

## 1. 一句话结论

把飞鸽封装成本地平台在技术上成立：**登录**用浏览器自动化（阿里云滑块可程序化拖过），拿到 JWT 后，**通话列表、通话详情、录音下载、转写文本、呼出、实时状态**都可以用纯 HTTP + WebSocket 完成；登录态 7 天有效。主要限制是：**本账号只有「电信回拨」线路，没有 SIP 专线**，所以「呼出」必须经过被叫坐席绑定的手机回拨完成，暂不能做到无人工的全自动外呼。

## 2. 登录与会话

### 2.1 登录页与验证码

- 站点：`https://feige.duofangtongxin.com/#/login`，Vue 2 SPA，标题「智能外呼CRM后台管理系统」。
- 三种登录方式：短信验证码 / 密码登录 / 微信扫码。
- 密码登录表单：手机号 + **阿里云验证码 2.0 滑块**（`请按住滑块，拖动到最右边`）+ 密码。
- 滑块 DOM：`#aliyunCaptcha-sliding-wrapper` / `#aliyunCaptcha-sliding-slider`（页面内嵌，非 iframe）。
- 阿里云验证码初始化（前端源码 `chunk-6fc3dc88`）：

```js
window.initAliyunCaptcha({
  SceneId: 'm5ogf646',
  mode: 'embed',
  element: '#captcha-element',
  button: '#captcha-button',
  slideStyle: { width: 360, height: 40 },
  language: 'cn',
  success: (param) => { this.loginForm.captchaVerifyParam = param },
  ...
})
```

- 验证码服务域名：`dqklqn.captcha-open.aliyuncs.com`（验证）、`upload.captcha-open.aliyuncs.com`（设备指纹上传）、`dqklqn-verify.captcha-open.aliyuncs.com`（服务端 VerifyCaptchaV3）。
- **滑块实测可通过程序化鼠标轨迹通过**：`mouse.down → 36 步带缓动/微抖动的 mouse.move → mouse.up`，一次通过，页面出现「验证通过!」。
  - 轨迹需满足缓动（ease-out）+ 步长不均匀 + 少量 y 抖动；纯 `dragTo` 两段式不可靠。
- 通过后得到 `captchaVerifyParam`：Base64(JSON)，内容形如
  `{certifyId, sceneId:"m5ogf646", isSign:true, securityToken}`，随登录请求提交，由上游服务端向阿里云校验。

### 2.2 登录接口

```
POST https://feige.duofangtongxin.com/duofang-feige-admin/sso/login
Content-Type: application/json

{
  "mobile": "156****0075",
  "username": "156****0075",
  "password": "<明文密码>",
  "captchaVerifyParam": "<阿里云验证码返回的 Base64 参数>",
  "origin": "3",
  "remember": "1",
  "invite": "",
  "loginType": "B1"
}
```

响应：

```json
{ "code": 200, "message": "success", "data": "<JWT>" }
```

- JWT：`HS256`，payload 含 `userId / username / remember / origin / loginId / iat / exp`，**有效期 7 天**（exp-iat=604800s）。
- 其他返回码：`206` 表示需要改密 / 二次验证（前端进入改密流程）；密码或验证码错误会重新初始化滑块。
- 前端拿到 JWT 后：`localStorage` 存用户信息 + `setCookie("CLOUD_TOKEN", JWT)`（JS 写入，非 HttpOnly，域 `feige.duofangtongxin.com`）。
- 服务端另外下发 HttpOnly cookie：`CLOUD_TOKEN`（父域 `.duofangtongxin.com`）、`FEIGE_CLOUD_TOKEN`，用于其他云侧流程；**业务 API 不依赖它们**。

### 2.3 API 鉴权（重要）

- 所有业务接口路径前缀：`https://feige.duofangtongxin.com/duofang-feige-admin`
- 鉴权头：`cloud-token: <JWT>`
- **纯 HTTP 可用**：实测只带 `cloud-token` + `content-type: application/json`，不带 cookie/UA/Origin/Referer，接口正常返回。
- 失效语义（实现时要处理）：
  - 无 token：HTTP 200，body `{"code":401,"message":"登录已失效,请重新登录"}`
  - token 非法/过期：**HTTP 200 且 body 为空**（Content-Length: 0）→ 需按空响应判定为登录失效
- 建议：本地平台按账号保存 JWT + 过期时间；失效时触发该账号的重新登录（浏览器流程）。

### 2.4 实时通道（WebSocket）

```
wss://feige.duofangtongxin.com/duofang-feige-admin/ws/websocket?token=<JWT>
```

- 纯文本帧协议，不是 STOMP；客户端连上后发 `连接成功`、定时发 `ping`，服务端回 `pong`。
- **Node 端直连验证通过**（无需浏览器），可作实时事件/保活通道。
- 通话过程中会推送哪些消息尚未验证（需要一次真实呼出，见 §7 待验证项）。

## 4. 录音

- 字段：列表中的 `preRecordUrl`，**绝对 URL**，格式：
  `http://112.192.20.62:9876/cloud-api/record/{YYYYMMDD}/{telB}_{callId}_{md5}.wav`
- 实测可直接 `GET` 下载（HTTP 200/206，`application/octet-stream`），**无需鉴权**；文件名不可自行构造（含 hash），必须用接口返回的 URL。
- 前端播放时会把地址改写为 HTTPS 代理：
  `http://112.192.20.62:9876` → `https://feige.duofangtongxin.com`（同路径），实测 HTTPS 代理可下载。
  → 本地平台优先走 HTTPS 代理（TLS + 不受混合内容限制），直连 IP 作兜底。
- 音频格式：WAV，实测（本地下载后用 WAV 头解析）为 **8kHz / 16bit / 双声道（A/B 分声道）PCM**；15.06s 样本 481,964 bytes ≈ 32 KB/s ≈ **115 MB/小时**（与 16k mono 同码率，存储规划不变）。
  - 实测意义：**双声道 A/B 可直接拆分做说话人分离**（docs/13 §4.1 路径 A），无需 diarization。
- 录音应在通话结束后尽快拉取（上游保留期未确认，见 §9）。

## 5. 转写（上游已提供，覆盖不完整）

> **v1 决策（2026-11-14）**：**不使用上游转写**。本节仅作为上游能力侦察记录；产品流水线的转写全部由本地自建 ASR（MiniMax）完成，规格见 [13-后处理规格（ASR与LLM）.md](./13-后处理规格（ASR与LLM）.md)。

### 5.1 接口

```
POST /base/call/detail/call-detail-content
{ "id": "<callId>" }
```

响应（已接通且有转写时）：

```jsonc
{
  "code": 0, "msg": "success",
  "data": {
    "bindId": "<callId>",
    "content": "{\"payload\":{...}}"   // 注意：content 是 JSON 字符串，需要二次解析
  }
}
```

`content` 解析后：

```jsonc
{
  "payload": {
    "checkStatus": 3,                  // 3=SUCCESS
    "status_code": "21050000", "status_text": "SUCCESS",
    "rec_duration": 15060,             // 毫秒
    "biz_duration": 15060,
    "task_id": "2121158492397961217",  // 上游转写任务ID
    "sentences": [
      { "begin_time": 830, "end_time": 2230, "text": "喂。", "channel_id": 1,
        "emotion_value": 5.8, "speech_rate": 42, "silence_duration": 0 }
      // ...
    ]
  }
}
```

- 句级时间戳（毫秒，相对录音起点）、文本、`channel_id`、情绪值、语速、停顿。
- **声道即说话人**：`channel_id=0` 为主叫/坐席，`channel_id=1` 为被叫/客户（已用多个样本交叉验证：坐席开场「喂，李总，你好」「我是看你们…」在 channel 0，客户「喂。」「嗯。」在 channel 1）。
- 无转写时：`data: null`（未接通，或部分短通话）。

### 5.2 覆盖率（重要）

抽样最近 12 通「已接通」通话：8 通有转写（`checkStatus=3, SUCCESS`），4 通 `data=null`，且无转写样本时长都 ≤10s。

→ **不能假设上游一定给转写**。本地平台需要：
1. 有上游转写 → 直接落库 + 做词表归一；
2. 无上游转写 → 本地 ASR 兜底（16kHz mono WAV 非常适合）；
3. 说话人分离：上游通过双声道解决；本地兜底时也可靠双声道切分（若回拨录音保持声道分离），否则用 diarization。

### 5.3 其他相关接口

- `POST /base/ai-record-analysis/page`、`/base/ai-record-analysis/one`：AI 质检/分析模块，**本账号 403（无权限）**，不可依赖。
- 上游「质检」与拨打权限绑定：企业若被上游禁用质检则不可拨号（前端提示 `您所在企业被上游质检禁用，暂不可拨号`）→ 说明转写/质检是上游套餐能力的一部分，换账号/换企业时要探测该能力是否可用。

## 6. 呼出（关键项，尚未完成真实拨测）

### 6.1 前端呼出链路（源码分析）

```
点击拨打
  → GET  /base/crm/getExistOther?mobile=<号码>      # 查重（客户是否已存在）
  → POST /base/crmV2/callV2 { telB, interfaceId }   # 真正呼出
  → 响应 { code:0, data:{ bindId } }
  → 线路模式分支：
      · 普通回拨线路（本账号 interfaceId=9）：服务端先呼坐席绑定手机，再接客户
      · interfaceId=2（SIP专线）：浏览器 SIPml/WebRTC 呼出（需要「中间号」绑定）
      · interfaceId=888：本机拨打（本地助手 ws://127.0.0.1:8800，ATD/ATH 命令）
      · interfaceId=999：本机SIM卡拨号（飞鸽 App 自动拨号）
```

其他呼出相关接口：
- `GET  /base/api/agent/callLineList` → 账号可用线路：**本账号返回 `[{lineName:"电信回拨", lineId:9, mode:1}]`（仅回拨，无 SIP 专线）**
- `GET  /base/sys/userLine/getOne` → 当前选择的线路偏好
- `GET  /base/crm/querySipPassword?lineId=<id>` → SIP 账号密码（仅 SIP 线路可用；本账号 `lineId=2` 返回 `10056 用户未绑定中间号`）
- `POST /base/crm/automatic/call` / `/base/crm/un-automatic/call` → 飞鸽 App 自动拨号开关
- SIP 基础设施（源码里可见）：`SIPml.Stack({ realm:"47.96.236.10:39468", websocket_proxy_url:"wss://fs.duofangtongxin.com:7443" })`

### 6.2 本账号可用的呼出方式

- 线路：**电信回拨（lineId=9, mode=1）**
- 语义：调用 `callV2` 后，上游先呼叫坐席绑定手机 `telA=156****0075`，坐席接听后由上游桥接客户 `telB`。
- 对本地平台的含义：
  - ✅ 可以程序化「发起呼出」（HTTP 调用 callV2），状态与录音/转写随后从列表/详情接口取；
  - ⚠️ 通话本身必须有人（坐席手机）接听并完成，**不是无人值守的 AI 外呼**；
  - ❌ 本账号无法做「AI 语音机器人直接对客户讲话」：那需要 SIP 专线（lineId=2 / 中间号），当前账号未开通。
- 若后续开通 SIP 专线：可在 headless 浏览器内驱动页面 SIPml（WebRTC）实现程序化外呼与音频接入，属于二期能力。

### 6.3 真实拨测（已发起，被上游时间窗口拦截）

2026-11-13 22:42 实际发起一次拨测（测试被叫 `133****2072`，UI 拨号盘），捕获到的真实请求：

```
GET  /base/crm/getExistOther?mobile=133****2072
→ 200 {"code":0,"msg":"success","data":0}        # data=0 表示号码可拨（未命中客户查重/占用）

POST /base/crmV2/callV2
body: {"telB":"133****2072","interfaceId":1}
→ 200 {"code":10056,"msg":"拨打时间段在7:50-22:00之间","data":null}
```

**结论：**
- `callV2` 请求契约已确认：`{telB, interfaceId}`，其中 `interfaceId=1` 来自当前坐席线路选择（localStorage `lineselect`），上游话单里记录的 `interfaceId=9` 是实际线路 ID（服务端映射）。
- **上游强制「拨打时间段 7:50–22:00」**（服务器端业务规则，本地无法绕过）。拨测时 22:42，被拒。
- `code=10056` 是通用业务错误码（不同 message 表示不同原因），本地平台需按 message 分类并透传可读错误。
- 呼出前电话不会响铃（请求被拒即终止）。

因此「成功呼出 → 状态流转 → 录音/转写生成时延 → WS 推送格式」的验证顺延到下一个 7:50–22:00 窗口内进行。

## 7. 多账号

- 每个账号 = 一次独立登录 = 独立 JWT + 独立线路绑定 + 独立手机号（telA）；JWT 里含 userId/tenant。
- 话单查询按登录账号隔离（只返回自己话单）→ 本地库用 `account_id + call_id` 唯一键，天然不重复。
- 阿里云验证码依赖浏览器指纹/设备 token，**每个账号建议独立浏览器 profile（持久化上下文）**；多账号共用同一指纹/同 IP 有风控风险，需要限速与错峰。
- 本地平台结构：账号池（每账号：凭证、浏览器 profile、JWT、线路列表、健康状态）+ 每账号独立的 HTTP 客户端与同步游标。

## 8. 对架构的直接影响（按你的图）

```
Agent → SKILL → REST / CLI / MCP
                    │
        本地平台（北向统一契约）
        ├── 账号/会话管理：浏览器自动登录（阿里云滑块）+ JWT 池 + 保活/重登
        ├── Dialer：callV2 呼出 + 状态机（pending → calling → answered/unanswered）
        ├── Sync：getPage 增量拉话单（游标=startTime/updateTime）+ WS 实时事件
        ├── Fetcher：录音下载（HTTPS 代理/直连）+ 上游转写拉取（call-detail-content）
        ├── Processor：缺转写时本地 ASR；说话人（上游 channel / 本地 diarization）；词表归一（复萌/福梦→孚盟）
        └── Storage：SQLite（话单/转写/任务状态）+ 原始 WAV（原样留档，可重跑）
```

关键点：
- **北向（REST/CLI/MCP）**：Dail / Dial Status / getOutboundList / OutboundList / getOutboundDetail / OutboundDetail / getStatus 都能映射到已确认的上游能力。
- **南向**：登录需要浏览器（仅登录时），其余全部纯 HTTP/WS → 本地平台大部分时间不需要浏览器，稳定性和资源占用都可控。
- **异步流水线**（对应需求 5.1）：呼出后建 pending → 轮询/WS 捕捉接通 → 取录音 → 上游转写（缺失则本地 ASR）→ agent 处理（说话人 + 词表归一）→ 入库。
- `getStatus`（平台健康）可用：JWT 剩余有效期、WS 连通、`userDetail` 可用性、`callLineList`、余额 `pay/find`、最近同步时间。
