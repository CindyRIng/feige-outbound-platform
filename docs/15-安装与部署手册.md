> 版本：v0.3.0（2026-11-14）｜适用：Linux（已在 NixOS 验证）、Node.js ≥ 22.5
> 本文覆盖：环境要求 → 安装 → 配置 → 启动 → systemd 常驻 → 无显示服务器 → 备份/升级 → 监控/排障 → 验收。
> 架构与能力见 [README](../README.md)；接口契约见 [docs/05](05-对外API契约.md) / [spec/openapi.yaml](../spec/openapi.yaml)。

## 1. 部署总览

```
┌──────────────────────────── 本机（默认仅 127.0.0.1） ────────────────────────────┐
│  CLI(feige) / MCP / SKILL / Swagger UI / curl                                   │
│         │ HTTP + Bearer token                                                   │
│         ▼                                                                       │
│  feige-outbound-platform 服务（systemd user service）                           │
│    Fastify REST v1 :8710 ── core（账号/同步/呼出/流水线/作业/事件）             │
│         │                       │                                               │
│         ▼                       ▼                                               │
│  ~/.config/feige-outbound/   ~/.local/share/feige-outbound/                     │
│   config/secrets/token/env    fop.db · audio/ · asr/ · profiles/ · logs/        │
└──────────────┬──────────────────────────────┬──────────────────────────────────┘
               │ HTTPS/WSS                    │ HTTPS
               ▼                              ▼
        飞鸽上游（登录/话单/呼出/录音）     MiniMax ASR · DeepSeek LLM
```

- 默认**仅监听 127.0.0.1**，不需要公网入站；只需要出站 HTTPS/WSS 可达上游与 AI 服务。
- 服务与 CLI/MCP 分离：CLI/MCP 可以跑在同一台机器（经 REST 调用），也可以远程调用（自行加代理/TLS）。

## 2. 环境要求

### 2.1 最低配置

| 项 | 要求 | 说明 |
| --- | --- | --- |
| CPU/内存 | 2 vCPU / 2GB RAM 起 | ASR/LLM 在云端；本地主要是下载/切片/DB |
| 磁盘 | ≥ 20GB 可用 | 录音约 115MB/小时；1000 通×3min ≈ 5.8GB；ASR 缓存/日志另计 |
| 操作系统 | Linux（systemd 可用） | macOS 可用（用 launchd 替代 systemd）；Windows 未验证 |
| Node.js | **≥ 22.5**（建议 22 LTS） | 依赖内置 `node:sqlite`（ExperimentalWarning 正常） |
| 浏览器 | Chromium/CloakBrowser + 显示 | **仅自动登录用**；无显示用 Xvfb（见 §7） |
| 网络 | 出站 HTTPS/WSS | 上游域、录音存储、`api.minimax.cn`、`api.deepseek.com` |

### 2.2 网络出站白名单（仅 443）

| 域名 | 用途 |
| --- | --- |
| `feige.duofangtongxin.com` | 上游 HTTPS API 与 WSS |
| 录音存储域（上游返回的 `preRecordUrl`） | 录音下载（示例为 `112.192.20.62:9876`，以实际 URL 为准） |
| `api.minimax.cn`（或 `api.minimax.io`，与 key 区域匹配） | ASR |
| `api.deepseek.com` | LLM |

> 不需要公网入站端口；若通过反向代理暴露 8710，请自行加 TLS 与访问控制（见 §8）。

## 3. 安装

### 3.1 方式 A：Git 源码安装（推荐）

```bash
git clone https://github.com/CindyRIng/feige-outbound-platform.git
cd feige-outbound-platform

# 依赖与构建（tsc + 复制 SQL 迁移/登录 worker/OpenAPI 资产）
npm install
npm run build

# 安装 CLI（符号链接到 dist/src/main.js；默认 ~/.local/bin）
npm run install:cli
feige --version        # 0.3.0
```

> `~/.local/bin` 需在 PATH 中；否则把 `npm run install:cli` 的输出目录加入 PATH，或手动：
> `ln -sfn "$PWD/dist/src/main.js" ~/.local/bin/feige`

### 3.2 方式 B：离线包

```bash
tar -xzf feige-outbound-platform-0.3.0.tar.gz
cd feige-outbound-platform
npm ci --omit=dev          # 生产依赖
npm run build
npm run install:cli
```

> `dist/` 不随 git 提交；发布包包含源码，需要在目标机器执行一次 `npm run build`（需要 Node）。

### 3.3 升级已有安装

```bash
cd feige-outbound-platform
sudo systemctl --user stop feige-outbound.service   # 或 systemctl --user stop ...
git pull
npm install
npm run build
npm run install:cli
systemctl --user start feige-outbound.service
systemctl --user status feige-outbound.service
```

数据库迁移在服务启动时自动执行（schema_version 校验/幂等）；升级前建议先备份（§10）。

### 3.4 目录说明

| 路径 | 说明 |
| --- | --- |
| 仓库/发布目录 | 代码、`dist/`、`spec/`、`deploy/`、`scripts/`、`docs/` |
| `~/.config/feige-outbound/` | `config.json`、`secrets.json`、`api-token`、`env`、`diagnostics/` |

## 4. 配置

### 4.1 密钥（必填）

`~/.config/feige-outbound/secrets.json`（**0600**）：

```json
{
  "minimaxApiKey": "sk-api-xxxxxxxx",
  "deepseekApiKey": "sk-xxxxxxxx",
  "accounts": {}
}
```

> `accounts` 由 `feige account add` 自动写入（含上游手机号/密码/浏览器 profile 名），请勿手工提交到仓库。
> 也可用环境变量（systemd `EnvironmentFile`）：`FOP_MINIMAX_API_KEY`、`FOP_DEEPSEEK_API_KEY`（优先级高于 secrets.json）。

### 4.2 AI 供应商

| 项 | 建议/默认 | 说明 |
| --- | --- | --- |
| ASR provider | `minimax` / `asr-1.0` | 中文短语音转写；`verbose_json` + sentence 时间戳 |
| ASR baseUrl | `https://api.minimax.cn` | **必须与 key 区域匹配**；global key 用 `api.minimax.io`，不匹配会 `401 invalid api key` |
| ASR 并发 | `1` | 实测 MiniMax 账号并发连接上限=1（2 并发即 429 `conn limit`）；可申请更高并发后调大 |
| LLM provider | `deepseek` / `deepseek-chat` | 失败升级 `deepseek-v4-pro`（max_tokens ≥ 4096） |
| LLM 并发 | `8` | DeepSeek 限流较宽松；按需调整 |

> 成本：ASR 按音频时长计费、LLM 按 token；全量回补可能产生数百次调用。首次部署建议先同步少量话单观察 `/status` 与账单。

### 4.3 config.json（非敏感，可选）

首次启动生成默认配置。常用项：

| 配置键 | 默认 | 说明 |
| --- | --- | --- |
| `server.host/port` | `127.0.0.1` / `8710` | 监听地址/端口（也可 `FOP_HOST/FOP_PORT`） |
| `storage.dataDir` | `~/.local/share/feige-outbound` | 数据目录 |
| `browser.headless` | `false` | 登录浏览器是否 headless（滑块建议 headful + Xvfb） |
| `dial.windowStart/End/timezone` | `07:50` / `22:00` / `Asia/Shanghai` | 全局可拨号时段（线路级可能更严） |
| `dial.scheduleOutsideWindow` | `true` | 时段外：排队（true）或拒绝 422（false） |
| `limits.perAccountConcurrency` | `1` | 单账号同时通话数（回拨模式 v1=1） |
| `limits.dialCooldownMs` | `60000` | 同号码冷却 |
| `sync.intervalMs` | `60000` | 自动增量同步周期（0=关闭自动同步） |
| `sync.lookbackDays` | `7` | 增量回看天数 |
| `pipeline.asr.concurrency` | `1` | ASR 并发（受 MiniMax 账号限制） |
| `pipeline.asr.chunkSeconds` | `420` | 长通话切块窗口（>480s 才切） |
| `pipeline.analysis.concurrency` | `8` | LLM 并发 |
| `pipeline.analysis.maxInputChars` | `120000` | 单次分析输入字符上限 |
| `events.webhooks` | `[]` | 事件 webhook（https） |
| `logging.level` | `info` | debug/info/warn/error |
| `runtime.keepAliveMs` | `60000` | 账号 health/WS 保活周期 |
| `security.maskPhones` | `false` | **PII 展示策略**：false=API/CLI 返回完整手机号（默认，本机单用户运营）；true=脱敏（日志始终脱敏，AI 输入仍按 `pipeline.analysis.redactPhones`） |

修改方式：

```bash
feige config get                         # 查看生效配置
feige config set pipeline.asr.concurrency=1
feige config set server.port=8710
# 或 REST（密钥字段禁止经 API 修改）
curl -X PATCH .../api/v1/config -H "Authorization: Bearer $TOKEN" -d '{"sync":{"intervalMs":120000}}'
```

> 配置改动的生效范围见 docs/10 §12（部分热生效，部分需重启服务）。

### 4.4 本地 API token

- 首次启动自动生成于 `~/.config/feige-outbound/api-token`（0600）；
- CLI 自动读取；REST 调用需 `Authorization: Bearer <token>`；
- 轮换：删除 token 文件并重启服务（旧 token 立即失效），或 `feige doctor --fix-token`（按实现提示）。

## 5. 上游账号准备

1. 在飞鸽网页端确认账号可用（手机号+密码），并确认是否绑定**电信回拨**线路；
2. `feige account add main --name 主账号 --username 156****0075 --password-stdin`（或 REST，见 README）；
3. `feige account login main`：
   - 服务会启动 CloakBrowser（headful）打开登录页，自动勾选协议、填写手机号/密码、拖动阿里云滑块，捕获 JWT；
   - 首次约 6–30s；成功后 `state=online`，JWT 约 7 天；
4. `feige account health main` 应返回 `online / upstream=true / line=电信回拨 / dialWindow`；
5. 服务会周期保活（health + WS ping）；JWT 过期或探测到 401 会标记 `expired`，需重新 `account login`（可 force 清 profile 重登）。

> 注意事项：登录依赖真实浏览器与显示；服务器无显示请先按 §7 配置 Xvfb。不要把浏览器 profile 拷贝到不可信机器。

## 6. systemd 常驻部署（推荐）

模板：`deploy/feige-outbound.service`（已包含最小权限沙箱：`ProtectHome=read-only` 等；`ReadWritePaths` 已放行数据/配置/浏览器缓存目录）。

### 6.1 安装与启动

```bash
cd feige-outbound-platform

# 可选：把密钥放进 EnvironmentFile（0600）
mkdir -p ~/.config/feige-outbound
cp deploy/env.example ~/.config/feige-outbound/env
chmod 600 ~/.config/feige-outbound/env
# 编辑 env 填入 FOP_MINIMAX_API_KEY / FOP_DEEPSEEK_API_KEY

mkdir -p ~/.config/systemd/user
cp deploy/feige-outbound.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now feige-outbound.service

systemctl --user status feige-outbound.service
journalctl --user -u feige-outbound.service -f
```

### 6.2 验证

```bash
feige health
feige status
curl -s http://127.0.0.1:8710/api/v1/docs -o /dev/null -w '%{http_code}\n'   # 200
```

### 6.3 常用运维

```bash
systemctl --user restart feige-outbound.service
systemctl --user stop feige-outbound.service
systemctl --user enable/disable feige-outbound.service
journalctl --user -u feige-outbound.service --since '1 hour ago' | tail -100
```

### 6.4 NixOS / 非标准环境说明

- 本机已在 NixOS user systemd 下验证（Node 由 `~/.nix-profile/bin/node` 提供，unit 用 `/usr/bin/env node` 查找 PATH）；
- 如果 user manager 的 PATH 不含 node，请把 unit 的 `ExecStart` 改为绝对路径：`ExecStart=/absolute/path/to/node --enable-source-maps dist/src/main.js serve`；
- 浏览器自动化需要 `DISPLAY`（见 §7）与可执行的 `~/cloak-env/bin/cloak-run`；unit 的 `ReadWritePaths` 已允许 `~/.cache`、`~/.local/state`、`~/.cloakbrowser`。

## 7. 无显示服务器（headless）部署

Sliding captcha 建议 **headful + Xvfb**（headless 可能更易被风控）。

```bash
# 安装 Xvfb（Debian/Ubuntu：apt install xvfb；NixOS：nix-shell -p xorg.xvfb）
cp deploy/feige-outbound-xvfb.service ~/.config/systemd/user/
systemctl --user enable --now feige-outbound-xvfb.service

# 让服务使用 Xvfb 显示（编辑 ~/.config/systemd/user/feige-outbound.service）
# Environment=DISPLAY=:99
systemctl --user daemon-reload
systemctl --user restart feige-outbound.service
```

> 登录异常时查看 `~/.local/share/feige-outbound/diagnostics/`（截图/日志）与 `journalctl`；worker 失败会自动重试 2 次，滑块失败会标记 needHuman。

## 8. 远程/反向代理（可选）

默认**不建议**直接暴露 8710。若确需远程访问：

1. 只允许内网/VPN 访问；
2. 用 Nginx/Caddy 终止 TLS，反代到 `127.0.0.1:8710`；
3. SSE 需关闭缓冲：Nginx 加 `proxy_buffering off;`、`proxy_read_timeout 3600s;`；
4. `/api/v1/docs` 与 `/api/v1/openapi.*` 为公开端点（无 token），如不希望暴露可在代理层限制来源 IP；
5. v1 只有单一本地 token，无多用户/权限模型；不要作为公网多租户服务。

## 10. 备份与恢复

### 10.1 备份内容

| 内容 | 路径 | 说明 |
| --- | --- | --- |
| 数据库 | `~/.local/share/feige-outbound/fop.db`（+ `-wal/-shm`） | SQLite WAL；建议在线备份或用 `sqlite3 .backup` |
| 录音 | `~/.local/share/feige-outbound/audio/` | 原始 WAV（可重新下载但上游可能过期） |
| ASR 缓存 | `~/.local/share/feige-outbound/asr/` | 可选（可重建，省成本） |
| 配置/密钥 | `~/.config/feige-outbound/` | **含敏感信息，加密保存** |
| 浏览器 profile | `~/.local/share/feige-outbound/profiles/` | 可选（含登录态，敏感） |

> 备份脚本建议先 `systemctl --user stop feige-outbound.service` 或使用 SQLite 在线备份接口，避免 WAL 不一致。

### 10.2 备份示例

```bash
BK=/backup/fop-$(date +%F-%H%M)
mkdir -p "$BK"
systemctl --user stop feige-outbound.service
sqlite3 ~/.local/share/feige-outbound/fop.db ".backup '$BK/fop.db'"
rsync -a ~/.local/share/feige-outbound/audio/ "$BK/audio/"
rsync -a ~/.config/feige-outbound/ "$BK/config/"
systemctl --user start feige-outbound.service
tar -C /backup -czf "$BK.tar.gz" "$(basename "$BK")"
```

### 10.3 恢复

```bash
systemctl --user stop feige-outbound.service
cp /backup/.../fop.db ~/.local/share/feige-outbound/fop.db
rsync -a /backup/.../audio/ ~/.local/share/feige-outbound/audio/
rsync -a /backup/.../config/ ~/.config/feige-outbound/
systemctl --user start feige-outbound.service
feige status && node scripts/reconcile.mjs
```

## 11. 监控与可观测

| 手段 | 用法 |
| --- | --- |
| 健康探针 | `GET /api/v1/health`（无副作用，可用 systemd/monitor 定时探测） |
| 平台状态 | `GET /api/v1/status`：DB/账号/时段/队列/回填计数/SSE 客户端 |
| 日志 | `journalctl --user -u feige-outbound.service -f`；文件 `~/.local/share/feige-outbound/logs/fop.log`（JSON lines，敏感字段脱敏） |
| 事件流 | `GET /api/v1/events/stream?types=call.*`（24 类事件：sync/audio/transcript/analysis/dial…） |
| 作业 | `feige jobs list` / `GET /api/v1/jobs`：队列积压、失败重试、耗时 |
| 对账 | `node scripts/reconcile.mjs`：按实际产物修正状态/取消积压（`--cancel-jobs`） |
| 磁盘水位 | 监控 `~/.local/share/feige-outbound` 容量（录音≈115MB/小时）与 `df`；接近阈值时暂停 `sync --full` |

建议告警：服务 down、`/status` 账号非 online、作业 queued 持续增长、磁盘 >80%、ASR/LLM 失败率升高。

### 11.1 词表变更后的历史数据刷新（v0.3.2+）

修改词表后，新转写会自动使用新规则；历史数据可用**重归一脚本**低成本刷新（不重跑 ASR/LLM，仅重算文本）：

```bash
npm run terms:renormalize              # dry-run：统计将变化的转写/分析数量与样例
npm run terms:renormalize -- --apply   # 落库：重算 normalizedText/full_text 与分析文本
```

- 保留 `full_text_raw`（ASR 原文）供追溯；`analysis.terms_applied_json` 会刷新命中统计；
- 单条验证可用 `feige calls transcript <callId>`；如需要彻底重跑（含 ASR/LLM）可用 `feige calls reprocess <callId> --stage transcript --stage analysis --yes`；
- 建议流程：改规则 → dry-run → apply → 抽查 → 记录变更（CHANGELOG/docs/13）。

## 12. 容量与性能

| 项 | 估算 |
| --- | --- |
| 录音 | 32KB/s ≈ **115MB/小时/路** |
| 1000 通 × 3 分钟 | ≈ 5.8GB 录音 + ASR 缓存（约 10–20%） |
| 全量回补 1000 通 | ASR 约 1000×2 声道请求（并发 1，约数小时）；LLM 1000 次（并发 8，约 20–40 分钟） |
| DB | 1 万通话单 ≈ 数百 MB（含事件/分段） |
| 建议磁盘 | 预留 ≥ 2× 录音总量（备份/切片临时文件） |

调优：
- 若 MiniMax 账号并发提高 → 调大 `pipeline.asr.concurrency`（不要超过账号上限，否则 429）；
- 全量回补建议分批：`feige sync --mode backfill --from YYYY-MM-DD --to YYYY-MM-DD --wait`；
- `pipeline.rawDump.enabled=true` 仅在排障时开启（会保存上游原始对象到文件）。

## 13. 安全加固

1. 服务仅监听 `127.0.0.1`（默认）；不要把 8710 直接暴露公网。
2. 文件权限：`~/.config/feige-outbound` 700，`secrets.json`/`env`/`api-token` 600，数据目录 700（服务自动创建）。
3. 密钥轮换：AI key 定期轮换；轮换后更新 `secrets.json`/`env` 并重启服务。
4. 账号安全：上游密码保存在 `secrets.json`（0600）；浏览器 profile 含登录态，禁止外传；不要提交到 git。
5. 日志：平台对手机号/JWT/API key 做脱敏；`includeRaw` 会返回上游原始对象（含手机号），仅调试时使用。
6. 合规：录音/转写含个人信息，请按《个人信息保护法》等要求取得授权、限制访问、设置保留期限；上游服务条款优先。**v0.3.1 起 API/CLI 默认展示完整号码**（业务决策），如服务将经反向代理/多人共享，请在 `config.json` 将 `security.maskPhones` 设为 `true`（或 `FOP_MASK_PHONES=true`）。
7. JWT 当前明文存于 0600 SQLite（`jwt_key_id=plain-v1`），后续版本将支持 `FOP_SECRET_KEY` 加密；在多用户主机的生产环境请限制文件访问/磁盘加密。

## 15. 常见问题（部署/运行）

| 现象 | 排查与处理 |
| --- | --- |
| `feige: command not found` | 未安装或 PATH 不含：`npm run install:cli`；`export PATH="$HOME/.local/bin:$PATH"` |
| `UNAUTHORIZED` | token 文件不存在/过期：`feige doctor`；重启服务重建 token；或 `--token`/`FOP_API_TOKEN` |
| 服务启动即退出 | `journalctl` 看错误：端口占用、DB 被锁、配置 JSON 非法、Node <22.5 |
| 登录失败/滑块 | 检查 DISPLAY/Xvfb、网络；查看 diagnostics 截图；`account login --force`；重试 |
| ASR 401 | key 区域与 baseUrl 不匹配（CN↔global） |
| ASR 429 `conn limit` | 并发过高：保持 `concurrency=1`；等待退避；申请配额 |
| 呼出 `CALL_OUTSIDE_DIAL_WINDOW`/`2516` | 全局 07:50–22:00；线路级可能 08:00 起；默认排队 10 分钟后重试 |
| 呼出 `5次/天` 限制 | 降低拨测频率；换测试号码或次日再测 |
| 磁盘增长快 | 监控 audio/；归档旧录音；`sync --full` 分批；清理 tmp |
| DB 锁/迁移错误 | 确认只有一个服务实例；`node scripts/reconcile.mjs` 对账；必要时从备份恢复 |
| Swagger UI 打不开 | 服务是否运行、8710 是否被占用；`/api/v1/docs` 需无需 token；检查浏览器控制台（favicon/source 资源） |
