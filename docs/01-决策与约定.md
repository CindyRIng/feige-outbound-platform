## 1. 项目定义

| 项 | 内容 |
| --- | --- |
| 项目名 | `feige-outbound-platform`（本地飞鸽外呼平台） |
| 代号 | FOP |
| 一句话 | 把飞鸽外呼（feige.duofangtongxin.com，仅网页/App、有人工坐席回拨）封装成本地可编程平台：多账号会话池 + 自动登录保活 + 呼出编排 + 话单/录音/转写沉淀 + AI 后处理，对外提供 REST / CLI / MCP / SKILL 四种入口。 |
| 上游 | 飞鸽外呼 `https://feige.duofangtongxin.com/duofang-feige-admin`（非公开 API，实测可用，存在改版风险） |
| 北向 | REST（HTTP/JSON，本地服务）、CLI（`feige` 命令）、MCP（stdio server）、SKILL（agent 侧技能包） |
| 运行形态 | 单机常驻服务（systemd user service），默认只监听 `127.0.0.1`；内置后台 worker（登录/同步/下载/转写/AI 后处理/任务队列） |
| 部署环境 | 本机 Linux（当前环境 NixOS），Node.js ≥22，浏览器自动化用 Playwright-core + CloakBrowser/Chromium（仅登录与需要浏览器时使用） |

### 1.1 目标（v1 范围）

1. 多上游账号（多坐席）会话池：自动登录（含阿里云滑块）、7 天 JWT 保活、失效自动重登、账号级限速与健康检查。
2. 只读同步：话单列表/详情、录音（WAV 原样存档）；**转写由本地 ASR 自建（MiniMax），不使用上游转写**。
3. 呼出编排：`Dial` 建 pending → 调度到账号 → 调上游呼出 → 状态机跟踪（接通/未接通/失败）→ 触发录音与转写流水线。
4. AI 后处理：说话人角色（坐席/客户）确认、领域词表归一（如 `复萌/福梦 → 孚盟`）、结构化产出（分段对话+摘要+意向），可重跑。
5. 对外契约：REST v1 + CLI + MCP + SKILL；`getStatus` 返回平台/账号池健康。
6. 可靠性：断点续跑（重启后任务不丢）、幂等、可观测（结构化日志、事件流、任务状态）。

### 1.2 非目标（v1 明确不做）

- **不做全自动 AI 语音外呼**：当前账号仅"电信回拨"线路，呼出必然先振铃坐席手机，需人工接听；无 SIP 专线（见侦察报告 §6）。若未来开通 SIP 专线，作为 v2 能力另行设计（WebRTC 软电话层）。
- 不做多租户 SaaS、不做公网暴露、不做 Web 管理前端（v1 用 CLI/MCP/REST；WebUI 仅未来可选）。
- 不改写/伪造上游 App、不逆向加密、不绕过上游风控与业务规则（含拨打时段、质检开关）。
- 不做 CRM 业务功能（客户管理、任务分配、话术库等仍是上游能力）。

### 1.3 用户与场景

| 角色 | 场景 |
| --- | --- |
| AI Agent（主） | 通过 SKILL/MCP/CLI 查询话单、检索转写、发起呼出、查询平台状态；对录音/转写做二次分析 |
| 销售/运营人员 | 用 CLI 快速拨号与查单；审阅转写与词表归一结果 |
| 平台维护者 | 账号接入、登录续期、同步巡检、故障排查（status/doctor/日志） |
| 二次开发者 | 通过 REST 集成到自己的系统 |

## 2. 术语表（全文统一）

| 术语 | 英文/字段 | 定义 |
| --- | --- | --- |
| 账号 | Account | 一个上游坐席账号（手机号+密码登录），对应一套浏览器 profile、JWT、线路与话单范围 |
| 会话 | AccountSession | 账号的登录态集合：JWT、cookie、WS 连接、健康状态 |

| 呼出 | Dial | 本地发起一通外呼（写操作，有副作用/计费）；对应上游 `callV2` |
| 回拨模式 | callback mode | 上游先呼叫坐席绑定手机（telA），坐席接听后桥接客户（telB） |
| 录音 | AudioAsset | 上游 `preRecordUrl` 指向的原始 WAV，本地下载归档（不可变） |
| 转写 | Transcript | 录音的文本化结果；v1 全部由本地 ASR（MiniMax `asr-1.0`）生成，不使用上游转写 |
| 分段 | TranscriptSegment | 转写的最小单元：起止时间、声道、原始文本、归一化文本 |
| 后处理 | Analysis | 对转写做说话人角色确认、词表归一、摘要/意向等结构化产出 |

| 平台状态 | Status | 平台自身健康（进程、DB、账号池、上游可达、拨打时段、队列积压） |
| 作业 | Job | 后台异步任务（login/sync/audio_fetch/asr/analysis/reprocess/backfill） |
| 事件 | Event | 状态变化通知（SSE 推送 + 可查询历史） |
| 拨打时段 | dial window | 上游强制可呼出时段 `07:50–22:00`（Asia/Shanghai，实测） |
| 坐席号 | telA | 主叫/坐席绑定手机号（上游话单字段 `telA`） |
| 客户号 | telB | 被叫/客户手机号（字段 `telB`；列表里也作 `phone`） |
| 线路号 | telX | 中间号/线路号（字段 `telX`） |
| 上游通话 ID | upstreamCallId | 上游雪花 ID 字符串（字段 `id`） |

## 3. 系统边界与部署形态

```
Agent ──SKILL──▶ CLI / MCP ──┐
                             ├──▶ 本地平台 REST(127.0.0.1:8710) ──▶ 平台内核
其他系统 ─────── REST ───────┘                                     │
                                                                   ├─ 账号/会话池 ──(登录浏览器/CloakBrowser)──▶ 上游
                                                                   ├─ 同步 worker ──(纯 HTTP/WS)────────────▶ 上游
                                                                   ├─ 呼出编排 (callV2/状态轮询/WS)──────────▶ 上游
                                                                   ├─ 媒体流水线 (录音下载/转写/ASR/AI 处理)
                                                                   └─ SQLite + 音频文件（本地存储）
```

- REST 基址：`http://127.0.0.1:8710/api/v1`（端口可配置，默认 8710）。
- 默认仅绑定 `127.0.0.1`；对外暴露必须显式配置并启用认证。
- CLI 与 MCP 是 REST 的**薄封装**：同一套操作，不重复实现业务逻辑（MCP 可直接调内核，但语义与 REST 一致）。
- 登录是唯一必须使用浏览器自动化的环节；其余全部纯 HTTP/WS（实测）。

### 3.1 进程模型

| 进程/模块 | 说明 |
| --- | --- |
| `feige serve` | 常驻主进程：HTTP API + 事件总线 + 调度器 + worker 池（单进程内并发，不做多进程） |
| 浏览器上下文 | 按账号懒启动、登录后关闭（或按需保活），登录时使用独立 profile 目录 |
| SQLite | 单文件数据库（WAL 模式），主进程独占 |
| 音频文件 | 本地文件系统，按日期分目录，DB 只存路径+hash |

## 4. 北向接口总览（四层关系）

```
Agent
 └─ SKILL（agent 侧技能说明，决定何时调什么）
     ├─ CLI `feige ...`（人类/agent 通用，--json 输出与 REST 同构）
     ├─ MCP tools `feige_*`（agent 原生，stdio）
     └─ REST /api/v1（其它系统/服务间）
```

原则：
1. **REST 是唯一业务契约**；CLI/MCP 的字段、错误码、状态枚举必须与 REST 一一对应（允许改名风格：REST 用 kebab/camel 统一 camelCase，MCP 工具名用 snake_case）。
2. 写操作（登录、呼出、重跑、同步触发）必须有明确副作用说明与失败语义。
3. 所有读接口可重复调用；所有写接口支持幂等键（见 §5.6）。

## 5. REST 通用约定

### 5.1 协议与编码

- HTTP/1.1，JSON UTF-8（`Content-Type: application/json; charset=utf-8`）；文件下载例外（`audio/wav`）。
- 路径统一 `/api/v1` 前缀；资源名用**复数小写**，路径参数 camelCase（`{callId}`）。
- 请求/响应字段：**camelCase**；时间字段后缀 `At`，时长字段后缀 `Ms`/`Sec`（含义见 04）。
- 所有响应带 `X-Request-Id`（客户端可传同名头覆盖，用于追踪）。

### 5.2 认证

- 方式：`Authorization: Bearer <localApiToken>`；token 存于 `~/.config/feige-outbound/api-token`（0600），首次启动生成。
- 默认仅本机可访问；配置 `server.allowRemote=true` 时必须启用认证且建议 TLS 反代（超出 v1 默认范围）。
- 认证失败：HTTP 401 + `UNAUTHORIZED`。

### 5.3 响应封套（Envelope）

成功：

```json
{
  "ok": true,
  "data": { },
  "meta": {
    "requestId": "req_01J8Z3K5T9QW2M4R7X1C6V0B8N",
    "ts": "2026-11-14T10:00:00+08:00",
    "pagination": { "page": 1, "size": 20, "total": 1073, "totalPages": 54 }
  }
}
```

失败：

```json
{
  "ok": false,
  "error": {
    "code": "CALL_OUTSIDE_DIAL_WINDOW",
    "message": "当前不在可拨号时段（07:50–22:00，Asia/Shanghai）",
    "retryable": true,
    "retryAfter": "2026-11-14T07:50:00+08:00",
    "details": {
      "upstreamCode": 10056,
      "upstreamMessage": "拨打时间段在7:50-22:00之间"
    }
  },
  "meta": { "requestId": "req_...", "ts": "2026-11-14T22:42:19+08:00" }
}
```

- `data` 与 `error` 二选一；`meta` 始终存在。
- 分页响应的 `meta.pagination` 仅在列表接口出现。
- HTTP 状态码与业务错误码**同时**表达：HTTP 表达类别，`error.code` 表达精确原因（见 §5.4）。

### 5.4 HTTP 状态码与错误码

| HTTP | 含义 | 典型 error.code |
| --- | --- | --- |
| 200 | 成功（读/更新） | — |
| 201 | 创建成功（如创建账号、发起呼出受理） | — |
| 202 | 已受理异步作业（login/sync/reprocess） | — |
| 204 | 成功无内容（DELETE） | — |
| 400 | 请求非法/参数校验失败 | `INVALID_REQUEST` `VALIDATION_FAILED` `CONFIG_INVALID` |
| 401 | 未认证/本地 token 错误 | `UNAUTHORIZED` |
| 403 | 被禁止（账号停用/远程未授权） | `ACCOUNT_DISABLED` `FORBIDDEN` |
| 404 | 资源不存在 | `NOT_FOUND` `CALL_NOT_FOUND` `ACCOUNT_NOT_FOUND` `JOB_NOT_FOUND` `TERM_NOT_FOUND` |
| 409 | 状态冲突/幂等冲突 | `CALL_ALREADY_TERMINAL` `CALL_NOT_CANCELABLE` `IDEMPOTENCY_CONFLICT` `ACCOUNT_BUSY` |
| 422 | 语义可解析但业务不允许 | `CALL_OUTSIDE_DIAL_WINDOW` `CALL_REJECTED_BY_UPSTREAM` `CALL_NOT_DIALABLE` |
| 429 | 触发本地限流 | `RATE_LIMITED` |
| 502 | 上游返回错误/不可解析 | `UPSTREAM_BUSINESS_ERROR` `UPSTREAM_RESPONSE_INVALID` `UPSTREAM_UNREACHABLE` |
| 503 | 依赖不可用（DB/上游登录态） | `UPSTREAM_AUTH_EXPIRED` `DB_UNAVAILABLE` `SERVICE_UNAVAILABLE` |
| 500 | 未预期错误 | `INTERNAL_ERROR` |
| 501 | 未实现（预留） | `NOT_IMPLEMENTED` |

**完整错误码表**（稳定契约，新增只增不改）：

| code | retryable | 说明 / 处理建议 |
| --- | --- | --- |
| `INVALID_REQUEST` | false | 请求结构错误、未知字段、非法 JSON |
| `VALIDATION_FAILED` | false | 字段值不合法（错误详情在 `details.fields[]`） |
| `CONFIG_INVALID` | false | 配置项非法或依赖缺失 |
| `UNAUTHORIZED` | false | 本地 API token 缺失/错误 |
| `FORBIDDEN` | false | 策略禁止（如远程访问未开启） |
| `NOT_FOUND` | false | 通用 404 |
| `CALL_NOT_FOUND` | false | callId 不存在 |
| `ACCOUNT_NOT_FOUND` | false | accountId 不存在 |
| `JOB_NOT_FOUND` | false | jobId 不存在 |
| `TERM_NOT_FOUND` | false | termId 不存在 |
| `ACCOUNT_DISABLED` | false | 账号被本地停用 |
| `ACCOUNT_LOGIN_REQUIRED` | true | 无有效 JWT，需先登录（`details.loginJobId` 可选） |
| `ACCOUNT_LOGIN_IN_PROGRESS` | true | 该账号登录作业进行中（返回 `details.loginJobId`） |
| `ACCOUNT_LOGIN_FAILED` | true | 登录失败（滑块/密码/二次验证），需人工介入或重试 |
| `ACCOUNT_BUSY` | true | 账号正在处理另一通呼出（回拨串行），返回 `details.busyCallId` |
| `ACCOUNT_UPSTREAM_MISMATCH` | false | 账号登录态与配置不一致（如换号） |
| `CALL_OUTSIDE_DIAL_WINDOW` | true | 不在上游拨打时段（07:50–22:00），`retryAfter` 给出下个窗口 |
| `CALL_REJECTED_BY_UPSTREAM` | false | 上游业务拒绝（余额/线路/质检禁用等），`details.upstreamCode/Message` |
| `CALL_NOT_DIALABLE` | false | 号码不可拨（空号/格式/黑名单/上游业务判定）；上游 CRM 查重命中默认**不阻断**（仅 warning，见 docs/05 §6.1） |
| `CALL_ALREADY_TERMINAL` | false | 话单已终态，当前操作不适用（`cancel` 一律拒绝；`reprocess` 对 `canceled` 拒绝，其余终态允许重跑流水线） |
| `CALL_NOT_CANCELABLE` | false | 仅 `pending` 可取消；已提交上游不可取消 |
| `CALL_TRACKING_TIMEOUT` | true | 呼出后超时未在上游查到话单（需人工核对，防重复呼叫） |
| `IDEMPOTENCY_CONFLICT` | false | 同一幂等键参数不同/并发冲突 |
| `RATE_LIMITED` | true | 本地限流（账号级/全局），`retryAfterMs`；429 适用于全部接口 |
| `UPSTREAM_UNREACHABLE` | true | 网络不可达/超时/5xx |
| `UPSTREAM_AUTH_EXPIRED` | true | 上游返回登录失效（空响应/401），需重登 |
| `UPSTREAM_BUSINESS_ERROR` | false | 上游业务错误（code≠0，非登录/时段类） |
| `UPSTREAM_RATE_LIMITED` | true | 上游限流（若出现；保守退避） |
| `UPSTREAM_RESPONSE_INVALID` | true | 上游响应结构不可解析（可能改版） |
| `AUDIO_NOT_AVAILABLE` | false | 该话单无录音（未接通/上游缺失） |
| `AUDIO_NOT_READY` | true | 录音尚未生成/下载中，稍后重试 |
| `AUDIO_DOWNLOAD_FAILED` | true | 下载失败（网络/URL 失效） |
| `TRANSCRIPT_NOT_AVAILABLE` | false | 无有效语音/本地 ASR 无法产出转写 |
| `TRANSCRIPT_PENDING` | true | 转写生成中/排队中 |
| `ASR_FAILED` | true | 本地 ASR 失败（可重试/换 provider） |
| `ANALYSIS_FAILED` | true | AI 后处理失败（LLM 错误/超时/JSON 不合法） |
| `DB_UNAVAILABLE` | true | SQLite 不可用/被锁 |
| `SERVICE_UNAVAILABLE` | true | 本地服务暂不可用（启动中/优雅关闭/传输被中断）；亦用于客户端侧「平台不可达」归一 |
| `INTERNAL_ERROR` | true | 未分类内部错误 |
| `NOT_IMPLEMENTED` | false | 预留能力 |

> **内部错误码**：适配层/后台作业内部可定义更细的错误码（见 [09-上游适配层契约.md](./09-上游适配层契约.md)），但**对外响应必须归一为上述 40 个稳定码之一**，不得把内部码直接暴露给北向调用方。

### 5.5 分页 / 排序 / 过滤

- `page`（1 起，默认 1）、`size`（默认 20，最大 100）；响应 `meta.pagination`。
- 排序：`sort` 形如 `-createdAt`（`-` 降序，即列表默认按受理时间倒序），默认 `-createdAt`；允许排序字段见 05。
- 时间过滤：列表接口统一用 `dateFrom`/`dateTo`（`YYYY-MM-DD`，Asia/Shanghai 自然日，含端点）过滤 `startedAt`；事件流用 `since`/`until`（ISO 8601）。**若与业务参数重名（如 `/calls` 的 `to` 表示被叫号码），禁止再使用 `from`/`to` 表示日期。**
- 文本搜索：`q`（对客户名/号码/转写全文做匹配，行为见 05）。

### 5.6 时间 / ID / 幂等

- 时间：ISO 8601 带时区（响应统一 `+08:00`）；上游毫秒时间戳转换后写入 `details.upstream` 原始值。
- ID：
  - `callId` / `jobId` / `eventId` / `termId`：本地 `ulid`（26 位，时间有序），前缀示例 `call_01J...`（统一用小写前缀 + ULID，如 `call_01J8Z...`）。
  - `accountId`：用户可读 slug（`[a-z0-9][a-z0-9_-]{1,31}`），如 `main`、`shouji-1`。
  - `upstreamCallId`：上游雪花 ID 字符串（19 位），**禁止**当本地主键。
- 幂等：
  - `POST /calls`、`POST /sync`、`POST /calls/{id}/reprocess`、`POST /accounts/{id}/login` 支持 `Idempotency-Key` 头（客户端生成 UUID/ULID）。
  - 相同键 + 相同请求体：24h 内返回首次结果（`meta.idempotencyReplayed=true`）；相同键 + 不同请求体：409 `IDEMPOTENCY_CONFLICT`。
  - **呼出防重**：同一 `accountId + to` 在 `details.dialCooldownMs`（默认 60s）内重复请求，若首单未终态返回 409 `ACCOUNT_BUSY`/`IDEMPOTENCY_CONFLICT`；禁止盲目重试 `callV2`（上游无幂等键，重复调用可能重复外呼）。

### 5.7 限流

| 维度 | 默认 | 可配置 | 备注 |
| --- | --- | --- | --- |
| 账号并发呼出 | 1（串行） | `limits.perAccountConcurrency` | 回拨模式下坐席手机同时只能一通 |
| 全局并发呼出 | 账号数 | `limits.globalConcurrency` | 多账号并行 |
| 上游读请求速率 | 每账号 5 QPS | `limits.upstreamReadQps` | 同步/详情/转写轮询共享 |
| 呼出冷却 | 同一号码 60s | `limits.dialCooldownMs` | 防重复呼出 |
| 本地 API 速率 | 100 QPS | `limits.apiQps` | 超出 429 |

### 5.8 版本化

- 路径版本 `/api/v1`；破坏性变更升 `/api/v2`，v1 至少保留一个里程碑周期。
- 响应新增字段视为非破坏性变更（客户端需忽略未知字段）；枚举新增值同理（客户端需容错）。

### 6.1 核心枚举

**Call status（话单状态）**：

| 值 | 含义 | 可能来源 |
| --- | --- | --- |
| `pending` | 已受理，待调度/待提交上游（含时段外排队） | 本地创建 |
| `dialing` | 已提交上游，等待坐席接听/桥接 | 本地提交 `callV2` 成功 |
| `connected` | 已接通（上游 `callStatus=1`） | 同步/轮询 |
| `ended` | 已结束且接通（终态） | 上游终态 + `endTime` |
| `no_answer` | 未接通（终态，上游 `callStatus=2`） | 同步/轮询 |
| `failed` | 呼出失败（被拒/超时/上游异常，终态） | 本地/上游 |
| `canceled` | 本地取消（终态，仅 `pending` 可取消） | 本地 |

> 终态：`ended` / `no_answer` / `failed` / `canceled`。
> 说明：`connected` 是从上游观测到的中间态；上游话单更新有延迟，`connected` 最终会落到 `ended`（接通）或极端情况下 `failed`（跟踪超时）。

**Pipeline stage status（流水线阶段状态）**，每个阶段独立：

| 值 | 含义 |
| --- | --- |
| `pending` | 尚未开始/等待依赖 |
| `in_progress` | 处理中（`details.lastError` 可为空） |
| `ready` | 完成且结果可用 |
| `missing` | 上游无此产物（如未接通无录音） |
| `failed` | 失败（可重试，`details.lastError` 有错误码） |
| `skipped` | 明确跳过（策略/配置） |

三个阶段：`audio`（录音归档）、`transcript`（转写）、`analysis`（AI 后处理）。

**Transcript source**：固定 `asr`（本地 ASR，provider=minimax）；不再有 `upstream`/`hybrid`。
**Speaker role**：`agent`（坐席） | `customer`（客户） | `unknown`。判定：双声道 A/B 拆分时按声道归属；单声道时由 ASR diarization（S1/S2）+ 规则/LLM 角色映射确定（见 docs/13 §4）。
**Job type**：`login` | `sync` | `audio_fetch` | `asr` | `analysis` | `reprocess` | `backfill`。
**Job status**：`queued` | `running` | `succeeded` | `failed` | `canceled`。
**Event type**：见 §7。

## 7. 状态机与事件

### 7.1 Call 状态转移表

| 当前 | 事件/触发 | 目标 | 副作用 |
| --- | --- | --- | --- |
| — | `POST /calls` 受理 | `pending` | 建 call + `call.created` 事件；若在时段外则记录 `scheduledAt` 并等待 |
| `pending` | 调度器提交上游 `callV2` 成功 | `dialing` | `dialedAt`；启动跟踪作业；`call.dialing` |
| `pending` | 提交前校验失败（时段外/账号不可用/线路异常） | `failed` | `failedReason`；`call.failed` |
| `pending` | `POST /calls/{id}/cancel` | `canceled` | 停止调度；`call.canceled` |
| `dialing` | 观测到 `callStatus=1`（已接通） | `connected` | `answeredAt`；`call.connected` |
| `dialing` | 观测到 `callStatus=2`（未接通） | `no_answer` | `endedAt`；`call.no_answer`；audio→`missing` |
| `dialing` | 超时未查到话单（默认 120s） | `failed` | `CALL_TRACKING_TIMEOUT`；需人工核对防重复呼叫 |
| `dialing` | 上游拒绝/异常（提交后异常） | `failed` | `call.failed` |
| `connected` | 观测到最终话单（`endTime` 存在） | `ended` | `durationSec`；触发 audio/transcript 流水线；`call.ended` |
| `connected` | 跟踪超时/上游异常 | `failed` | 保留已知信息；`call.failed` |
| 终态 | 任意写操作（除 reprocess 流水线） | 拒绝 | `CALL_ALREADY_TERMINAL` |

补充约束：
- 不允许跳过 `dialing` 直接 `connected`（除非同步补数据发现历史话单，此时允许 `pending → connected` 的"补录"路径并在事件中标注 `reconciled=true`）。
- 本地状态与上游状态冲突时，**以上游为准**记录 `details.reconciledAt`，并通过事件暴露。
- 呼出提交必须遵守 `dial window`；时段外受理的 call 保持 `pending` 并排入窗口（默认行为可配置 `dial.scheduleOutsideWindow=true`，否则直接 422）。

### 7.2 流水线状态机

```
call.ended / connected(补录)
  audio:      pending → in_progress → ready | missing | failed
  transcript: pending → in_progress → ready | missing | failed   （本地 ASR：MiniMax asr-1.0；未接通=missing）
  analysis:   pending → in_progress → ready | skipped | failed   （本地 pipeline：DeepSeek；无转写/无语音=skipped）
```

触发规则（实现规格见 [13-后处理规格（ASR与LLM）.md](./13-后处理规格（ASR与LLM）.md)）：
1. `audio`：话单出现 `preRecordUrl` 即入队下载（未接通 → `missing`）。
2. `transcript`：**不使用上游转写**。WAV 归档后入队本地 ASR：≤480s 整段请求；>480s 按 420s 静音点切块（MiniMax 单请求上限 500s/50MB）→ 合并时间戳 → 说话人分离（双声道拆分优先，否则 ASR 自带 diarization）→ 角色映射（坐席/客户）→ 词表归一。失败重试 5 次，仍失败 → `failed`。
3. `analysis`：`transcript.ready` 后执行；DeepSeek 内置 pipeline（默认 `deepseek-chat`，校验失败升级 `deepseek-v4-pro`）产出摘要/意向/关键词/质量项；LLM 输出再做一次词表归一与 PII 检查。
4. 任一步失败进入 Job 重试（指数退避，默认上限 5 次），超限标记 `failed` 并推事件，等人工 `reprocess`。
5. `reprocess` 可单独重跑 `audio`/`transcript`/`analysis`，不改变 `Call.status`。
6. 未接通（`no_answer`）分支：`audio=missing`、`transcript=missing`、`analysis=skipped`（与 docs/04 §15.1 一致）。

### 8.3 上游状态 → 本地 Call.status

| 上游观测 | 本地 |
| --- | --- |
| 话单不存在（呼出后短时间内） | `dialing` |

| `callStatus=2` | `no_answer` |
| `callStatus=0` 且 `callType≠0` | 「已拨打(暂无话单)」→ 保持 `dialing`，超时则 `failed` |
| `callStatus=0` 且 `callType=0` | 按未接通处理 → `no_answer`（若与本地预期不符，以事件暴露） |
| 上游 `code=10056` 拨打时段 | 拒绝提交 → `failed(CALL_OUTSIDE_DIAL_WINDOW)` |

### 8.4 上游错误 → 本地错误

| 上游现象 | 本地归一 | 说明 |
| --- | --- | --- |
| HTTP 200 空 body（token 非法/过期） | `UPSTREAM_AUTH_EXPIRED` | 触发重登 |
| `{"code":401,...}` | `UPSTREAM_AUTH_EXPIRED` | |
| `{"code":10056,"msg":"拨打时间段..."}` | `CALL_OUTSIDE_DIAL_WINDOW` | 按 message 正则分类 |
| `{"code":10056,"msg":"用户未绑定中间号"}` | `CALL_REJECTED_BY_UPSTREAM` | 账号无此线路 |
| `{"code":10056,...}` 其他 | `CALL_REJECTED_BY_UPSTREAM` | 透传 `upstreamCode/Message` |
| 网络超时/5xx | `UPSTREAM_UNREACHABLE` | 指数退避 |
| JSON 解析失败/字段缺失 | `UPSTREAM_RESPONSE_INVALID` | 记录原始响应摘要 |
| 其他 `code≠0` | `UPSTREAM_BUSINESS_ERROR` | 透传 |

### 8.5 硬约束（来自实测，实现必须遵守）

1. **拨打时段 07:50–22:00（Asia/Shanghai）**，服务器端强制；本地调度器必须在时段内调用 `callV2`，时段外保持 `pending` 或拒绝（配置项）。
2. **每个话单归属单个坐席**：`getPage` 只返回当前登录账号自己的话单（实测 100/100 同 userId）；多账号拉取后按 `accountId + upstreamCallId` 去重聚合。
3. **回拨模式串行**：单账号同一时刻只能有一通呼出（坐席手机占用）。
4. **JWT 7 天**：需在到期前重登；重登走浏览器+滑块，失败进入人工介入队列。
5. **录音匿名可下载**，但 URL 含哈希不可构造，必须用接口返回值；上游保留期未知 → 通话结束后尽快归档。
6. **不使用上游转写**：上游转写覆盖不全且不可控（实测 4/12 短通话缺失）；v1 全部转写由本地 ASR（MiniMax）生成。
7. **录音为 8kHz/16bit/双声道 A/B（实测）**：默认按声道拆分分别 ASR 实现说话人分离（docs/13 §4.1 路径 A）；单声道文件才走 diarization 兜底。
7. **上游无幂等键**：本地呼出必须自建幂等与防重（见 §5.6）。

### 8.9 上游拨打时段与频率限制（2026-11-14 实测）

- 全局 UI 时段 07:50–22:00 之外，**线路级时段更严**：实测 07:52 被 `[电信回拨(2516)]当前时间段无法调用` 拒绝、**08:00 起放行** → 归一 `CALL_OUTSIDE_DIAL_WINDOW`（retryable）；派发失败时保留 pending 并在 10 分钟后重试（不置失败、不重复派发）。
- 同主被叫限制：**30 秒内仅 1 次 + 5 次/天**（上游话术），透传 `CALL_REJECTED_BY_UPSTREAM`。
- 真实拨测状态语义：受理→短暂 `callStatus=2`→接通后 `callStatus=1`（durable 记录以最终态为准）；录音可能延迟约 2 分钟生成（`missing→pending` 回补）。

```jsonc
{
  "apiToken": "...",
  "accounts": {
    "main": { "username": "156xxxxxx", "password": "<加密/引用>", "browserProfile": "main" }
  },
```
